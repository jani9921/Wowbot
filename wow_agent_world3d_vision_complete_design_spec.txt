WORLD OF WARCRAFT AUTONOMOUS AGENT
WORLD3D VISION – TELJES TERVEZÉSI SPECIFIKÁCIÓ
DESIGN SPECIFICATION V1
============================================================

DOKUMENTUM CÉLJA
================

Ez a dokumentum a World3D Vision alrendszer teljes megtervezése.

NEM implementáció.
NEM egy egyszerű YOLO/detector specifikáció.
NEM quest planner.
NEM navigation controller.

A cél egy olyan vizuális világreprezentációs rendszer megtervezése, amely a World of Warcraft kliens 3D viewportjából folyamatosan, időben követhető és bizonytalansággal kezelt információt állít elő az agent többi része számára.

A World3D Vision legyen az agent "szeme", de ne az "agya".

Feladata:

- a 3D játéktér elkülönítése a UI-tól;
- entity-k és világobjektumok detektálása;
- nameplate-ek és overhead cue-k felismerése;
- target/interact/quest szerepkörökhöz szükséges vizuális evidence előállítása;
- entity-k időbeli követése;
- occlusion és temporary loss kezelése;
- kamera- és ego-motion elkülönítése entity motiontől;
- relatív távolság/distance belief becslése;
- közeli scene geometry és traversability becslése;
- obstacle / entrance / door / stairs / ramp cue-k előállítása;
- interaction readiness vizuális evidence előállítása;
- local landmarkok építése;
- negatív evidence előállítása;
- active perception requestek támogatása;
- tooltip/nameplate/target frame evidence-dzsel történő semantic fusion;
- WorldModel számára normalizált World3D observationök előállítása;
- SearchSkill / TargetSkill / Navigation / InteractSkill / CombatSkill számára stabil, időben követhető vizuális API biztosítása.

NEM feladata:

- quest kiválasztása;
- quest objective klasszifikálása;
- waypoint/útvonal tervezés;
- billentyűk megnyomása;
- combat rotation;
- quest complete eldöntése;
- planner működés;
- közvetlen W/A/S/D steering.

A World3D csak ezt válaszolja:

"Mit látunk most a 3D világban?"
"Mi maradt valószínűleg ugyanaz az előző frame óta?"
"Mi mozog a kamerához képest?"
"Mi lehet interaktálható?"
"Merre látszik járható tér?"
"Milyen lokális entity/object/entrance candidate-ek vannak?"
"Mennyire biztosak ezek?"

============================================================
25. OCCLUSION MODEL
============================================================

Temporary visual loss gyakori.

Occlusion evidence:

- candidate disappears behind persistent obstacle;
- predicted trajectory enters occluder;
- surrounding track motion consistent;
- reappears near predicted location;
- nameplate persists while body disappears;
- body persists while plate disappears.

State transitions:

ACTIVE
→ PARTIALLY_OCCLUDED
→ OCCLUDED
→ REACQUIRED

OCCLUDED alatt:
track még használható rövid ideig,
de position confidence csökken.

Ne azonnal TARGET_LOST.


============================================================
26. LOST GRACE POLICY
============================================================

Track missing one frame != LOST.

Config:

track_lost_grace_ms
max_prediction_ms
max_reacquire_radius

A jelenlegi tick-count based loss helyett wall-clock time legyen elsődleges,
mert FPS / sensor rate változhat.

A meglévő visual approach kódban már felismert probléma, hogy tick-alapú miss count gépfüggő reakcióidőt adhat.

Végleges design:
count + elapsed-time kombináció.

- tud relative bearinget;
- tud distance trendet;
- tud interakciós readiness evidence-et;
- tud nameplate-et first-class cue-ként használni;
- tud lokális obstacle/traversability evidence-et;
- tud entrance candidate-et;
- tud negative evidence-et;
- tud local searcht támogatni;
- tooltip/target evidence-dzsel identityt erősít;
- confidence/freshness minden fontos state-en jelen van;
- nincs quest/business logic a detectorban;
- nincs input authority a Visionben;
- replayelhető;
- diagnosztizálható.
