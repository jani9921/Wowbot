## Corrections

1. `destination_distance.arrived` respects a destination's explicit positive
   stop/arrival radius, including a radius smaller than four yards. The
   real turn-in policy's 0.8-yard close-in survives ranking at three yards,
   instead of yielding to another quest. Once there, the existing exact
   soft-recipient gate and bounded WAIT still own the handoff. Invalid
   explicit radii cannot prove arrival. Default region tolerance is kept.
2. The existing TDB provider recognises one explicit "Convince/Persuade/
   Ask/Tell <exact NPC name> to <action>" instruction only when it maps
   unambiguously to one non-wait objective with at least two matching
   meaningful words. Exact creature templates supply candidate IDs; the
   current server/UI GUID must still match. Technical credit names reuse
   the shared proxy predicate and are never physical NPC candidates.
   Completed/future text rows cannot keep requesting the finished step.
   Ambiguous actors/objectives/options remain unresolved, not guessed.
3. A shared pure `dialog_recipient` helper uses the fresh addon-owned NPC
   window GUID even if the hard target cleared. Otherwise it preserves
   fresh selected-NPC evidence. The existing planning/skill/verifier paths
   use that same identity; exact row ID/name/coordinates, active quest,
   removed/conflicting actors and finite live clocks are checked. It does
   not manufacture a target or friendliness flag, issue input, or create
   another controller. Real quest credit remains the only progress proof.
4. Zero/empty GOSSIP_SELECT UI quest identity is pending, not WRONG_QUEST_UI.
   One click is followed by observation without reclicking; another real
   quest still fails, and missing confirmation still reaches the existing
   bounded deadline. Unknown identity is never interpreted as success.

No quest/NPC/option ID is hardcoded in production logic. Tests intentionally
use the observed IDs as fixtures. Shared authority, selected PID, bindings,
addon and capture backend are unchanged.
