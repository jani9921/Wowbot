## Root causes and incremental fixes

### Airborne evidence belongs to its episode

NavigationService retained `_falling_since` across cancellation and reset.
During RECOVER, landing is seen by the recovery verifier rather than the
inactive route's observe method. A fresh short airborne edge after the
resumed request could therefore include time from the older attempt and
immediately exceed the two-second sustained-fall threshold.

Cancellation/reset now clear the episode timer. An explicitly grounded
new request also clears it; replacing a request during the same ongoing
fall does not. Confirmed ledge hazards survive same-context cancellation,
FAST falling still releases movement, and sustained falls still fail.
The three-failure task budget is deliberately unchanged.

### Walking quality is not just shortest binary-walkable distance

The native Detour path branch previously used the default binary filter
while reporting the configurable Python-side 44-degree slope limit.
The native centered path and service's later offsets could create steep
segments despite this diagnostic value. The pure Python A* had a slope
transition check, but the actual live native route bypassed it.

The project-owned native filter now adds costs proportional to distance
for directional climbing, locally rough/steep polygon geometry, and
proximity to known mesh boundary edges. Internal triangle size/portal
length alone is not labelled a narrow road. All costs are >= the original
Euclidean cost, preserving A*'s lower-bound heuristic. Include/exclude
flags still reject disallowed terrain (including water under the walking
mask). A steep polygon is not wholly banned: travel along its contour can
be safe, and quantized steps must not disconnect ordinary stairs.

The [Detour filter contract](https://github.com/recastnavigation/recastnavigation/blob/main/Detour/Include/DetourNavMeshQuery.h)
supports this project-owned cost/filter extension; all relevant translation
units are compiled with DT_VIRTUAL_QUERYFILTER and 64-bit polygon refs.
No third-party source is edited or second navigation/input owner added.

Returned centered segments are checked against the configured grade with
a 0.6-yard step allowance. If default centering creates an unsupported
segment, at most two wider clearances (4/6 yards) are queried with the same
projected endpoint layers. Only a complete grade-supported result is
accepted; otherwise the route fails closed, never to a direct-line move.
The service's offset/simplification guard also respects that grade bound.

Native capability/configuration is explicit per map. An old unsupported
DLL cannot claim the new policy. The versioned
`native/bin/aipc_detour_walking_v1.dll` avoids overwriting a DLL loaded by
the old GUI; the existing older binary is retained, not used as a hidden
native policy fallback. The Python-only route fallback keeps its existing
conservative slope transition rule and does not acquire semantic road data.

## What is NOT implemented

The current MMAP loader carries ground/steep/water flags and geometry, not
a verified semantic network of the player's marked/textured roads. The
VMAP composition currently supplies vertical collision heights; it is not
a general horizontal collision/LOS oracle or a road label source.
This improvement prefers safer geometry; it cannot promise to follow the
visually painted road everywhere. Exact road-network preference needs a
separate verified road source or successful recorded route evidence. No
NPC patrol table, normalized seed map or guessed ROAD tag is substituted.
No VMAP query expansion or independent visual navigation brain is added.
