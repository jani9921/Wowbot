## Implemented corrections

1. Server **selection** is independent of stream **health**. An explicitly
   selected/configured server runtime, or an established packet stream,
   does not silently regain visual input on stale/empty data. Offline worlds
   with neither configuration nor packet history retain their old policy.
   Explicit `AIPC_SERVER_MODE=0` still selects visual operation.
   Planner, admission, retained proposals, movement interrupts, pointer gate,
   parallel attention, navigation fallback and screen-loot policy share this
   selection. Health remains separately observable as `active`.
2. Entity state is coalesced by GUID/kind outside the discrete FIFO. Create
   and remove supersede pending earlier state; flags/position cannot undo a
   pending removal. Quest/combat/loot/teleport events retain their FIFO.
   The inbox prunes expired records before choosing its bounded fresh batch
   and reports their original stale counts without restamping them.
3. Snapshot recovery uses 5/10-second backoff and at most three attempts per
   unhealthy episode, including failed descriptor writes. A five-second
   observed healthy stream may reset the budget. Snapshot replay sends at
   most 64 cached entries per 0.5 seconds, resolving the current cache at
   send time; a removal during replay cannot be undone by an old create.
   The existing Ymir bridge can advance the replay even on records with no
   semantic event. No parser layout/build/allowlist was broadened.
4. GUI receipt status distinguishes incoming socket traffic from fresh
   accepted semantic data; an overflowing/stale queue is not labelled as
   healthy receiving.
5. An exact-GUID detailed death event, at most three seconds old, can reject
   a combat TARGET when compact FAST omits death fields. Another GUID's or
   expired event is never used. Explicit live flags outrank an old event.
   Hover confirmation requires a recent post-hover sample and, when
   present, a coherent cursor sample; it adds no minimum click delay.
6. A **known elite** cannot be attacked just because it is selected while
   the player is globally in combat. A concrete numeric/GUID kill objective
   or a positive same-player attacker relation can authorize it. The guard
   covers policy, admission, Tab defence verification and the final command
   identity boundary. Ordinary non-elite multi-attacker defence is unchanged;
   a dead owned elite is still eligible for the existing loot verifier.
