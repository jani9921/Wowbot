## Incremental implementation

1. `TDBKnowledgeProvider` recognises direct receive/hear orders,
   instructions or briefing objectives naming an exact TDB NPC. It marks
   the existing objective TALK and retains exact actor templates. Unknown
   names and unrelated objectives do not acquire conversation authority.
   Proxy credits remain nonphysical and are not kill targets.
2. `QuestDialogPlanningPolicy` strips API color escapes and recognises a
   leading `(Quest)` label. A single usable labelled row wins over lore
   regardless of its position. It must correspond to exactly one open
   conversation quest at the exact live UI owner. A positive exported row
   quest ID can disambiguate related quests; no quest-ID guess is added.
3. Multiple labelled rows, multiple possible quests without a row quest
   ID, unavailable/invalid rows, unknown/removed/stale recipients and
   completed objectives remain withheld. They cannot fall back to lore.
   Legacy unmarked text matching retains its ambiguity guard, including
   ties across equally supported quests. No new action/control owner.
4. The unchanged shared skill rechecks the owner/row and returns one click;
   verification waits for actual quest credit. Neither UI opening, row
   selection nor an action SUCCESS is substituted for quest completion.

There are no production quest IDs, option IDs, NPC IDs or row indexes
hardcoded in these policies. Numbers above identify recorded evidence.
