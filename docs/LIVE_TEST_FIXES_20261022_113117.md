## Correction and invariants

NavigationService remains the sole navigation/input-control boundary.
Partial routes carry explicit data-only provenance in their route regions.
Their last anchor is a waypoint, not final goal/interaction evidence.
Arrival at that anchor retains the same MOVE/request and the original
endpoint, resolves fresh floor evidence and plans the next bounded leg.
TTL/danger and fall replans use the same bounds; no direct-line fallback,
floor-authority relaxation, unlimited retry, or permanent arrival latch.
Probe replanning cannot reset the request's finite deadline.

A geometric terminal result is also checked against the original request
arrival envelope, so a projected/incomplete mesh endpoint far away cannot
mark the quest region reached. Such a result is a typed PATH_BLOCKED.
Existing explicit quest-state/interaction/map-transition evidence remains
a separate verification path; this change does not invent quest credit.

TravelModePolicy now observes mount transitions on every fresh engine tick,
not only when ordinary planner candidates are built. A known combat
dismount can prepare mounting for the next sufficiently long route without
adding an arbitrary 20-second post-combat delay. Ordinary dismount delay,
mount-failure backoff, action usability/cooldown, owned mount/riding,
selected bindings, unsafe-context and registry/goal/loop gates remain.

Resumed supervisor and recovery MOVEs pass through that same travel policy.
Preparing MOUNT does not consume either route's resume ownership. Local
loot/object work keeps precedence. A location commitment cannot replace a
validated preparatory mount with immediate walking. No extra planner,
input authority, entity identity shortcut or client-control mechanism.
