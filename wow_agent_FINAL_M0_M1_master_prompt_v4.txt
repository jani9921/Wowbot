============================================================
1. DEFINITIONS: OBSERVATION, BELIEF, FACT, INTENT, SKILL
============================================================

OBSERVATION
-----------
A sensor-specific statement.

Examples:
- "yellow quest-like icon detected at screen x,y"
- "target frame text reads X"
- "quest tracker line changed from 3/8 to 4/8"
- "minimap marker at angle 42 degrees"

An observation is not automatically true world state.


BELIEF
------
A fused interpretation derived from one or more observations.

Examples:
- "entity_42 is probably the required NPC"
- "objective area is probably in the northeast of this zone"
- "player is probably within interaction range"

A belief must have:
- confidence
- evidence list
- source timestamps


CONFIRMED FACT
--------------
Use only when the evidence source is sufficiently reliable for that fact.

Examples:
- explicit quest objective progress changed
- target frame shows target dead
- quest state reports ready for turn-in
- a blocking loading screen is visible

Do not promote weak vision evidence to fact.


INTENT
------
A high-level request given to a skill.

Examples:
- MoveToArea(location)
- Interact(entity)
- Combat(entity)
- Loot(corpse)
- SearchForEntity(query)


SKILL
-----
A deterministic state machine that executes ONE bounded capability.

A skill owns its internal progress until:
- SUCCESS
- FAILURE
- CANCELLED
- BLOCKED

A Planner does not micromanage a RUNNING skill.

============================================================
6. RUNTIME TICK CONTRACT
============================================================

The main runtime loop must be simple orchestration.

Conceptual pseudocode:

while running:

    observations = sensors.poll_or_consume()
    world_model.ingest(observations)
    world_model.expire_stale_evidence()

    events = event_bus.consume()

    supervisor.handle_interrupts(world_model, events)

    if active_skill.exists:
        result = active_skill.tick(world_model, now)
        executor.dispatch(result.commands)

        if result.status == RUNNING:
            continue

        if result.status in [SUCCESS, FAILURE, BLOCKED, CANCELLED]:
            supervisor.consume_skill_result(result)
            active_skill.finalize()

    if no_active_skill:
        next_intent = supervisor.next_intent(world_model)

        if next_intent:
            active_skill.start(next_intent)

IMPORTANT:

Do not call the planner every frame.

Do not replace a RUNNING skill merely because the planner can produce another action.

Replanning occurs only on an explicit gate.


============================================================
7. REPLAN GATES
============================================================

Planner/Supervisor may select a new high-level intent when:

- there is no active skill
- active skill SUCCESS
- active skill non-recoverable FAILURE
- active skill retry budget exhausted
- active skill BLOCKED and escalation is required
- world context fundamentally changed
- player died
- quest objective changed
- quest became ready for turn-in
- explicit higher-priority interrupt occurred

Do NOT replan because:
- a skill is still RUNNING
- one frame temporarily lost a target
- a minimap marker momentarily disappeared
- one detector confidence dipped briefly

============================================================
14. QUEST SUCCESS HAS TWO LEVELS
============================================================

THIS IS CRITICAL.

SKILL SUCCESS IS NOT QUEST SUCCESS.

Example:

CombatSkill SUCCESS:
target was killed.

But QuestProgressVerifier may report:

objective remained 3/8.

Therefore:
the combat action succeeded,
but the quest execution did NOT progress.

Likewise:

LootSkill SUCCESS
does not prove the required quest item was obtained.

InteractSkill SUCCESS
does not prove the quest objective advanced.

Always separate:

ACTION_SUCCESS
from
QUEST_CREDIT_CONFIRMED


============================================================

============================================================

Secondary evidence does NOT replace quest credit verification when quest state is available.

18. WORLD MAP RESOLVER
============================================================

WorldMapResolver is a first-class module.

Responsibilities:

- open/close map through configured input
- determine current map context
- distinguish current local map from parent zone/region when possible
- detect player map position/heading cue when available
- detect relevant quest markers
- detect ready-for-turn-in markers
- detect quest areas/bounds
- detect campaign/important/in-progress cues where available
- detect known entrance/teleporter/transport/map icons where useful
- inspect quest focus/supertracking/navigation destination if present
- produce a LocationBelief
- never directly control movement


18.1 Map zoom/context problem
-----------------------------

Absence of a marker at the current map level does NOT prove no marker exists.

Handle:
- wrong zoom level
- parent zone
- subzone
- interior/local map
- cave/floor context

Resolver procedure when expected marker is absent:

1. verify correct tracked quest
2. inspect current map level
3. zoom/step out if necessary
4. inspect relevant parent zone
5. if target zone found, zoom into it if useful
6. restore a usable map state
7. return location belief or UNKNOWN


18.2 Map filters
----------------

Map filters can hide content.

Do not treat hidden-by-filter as impossible.

If the implementation can reliably detect filter state, record it.

If it cannot, low-confidence absence must remain UNKNOWN, not confirmed absence.


18.3 Map location output
------------------------

Do not assume a screen pixel on the World Map is a direct 3D world point.

Return semantic/map-relative location evidence.

Navigation converts this into a movement strategy.

64. MAP / MINIMAP / 3D RELOCALIZATION LOOP
============================================================

This is the core quest-navigation loop:

while objective not complete:

    if validated local target exists:
        execute appropriate skill
        verify quest credit
        continue

    if usable local/minimap cue exists:
        navigate locally
        reobserve
        continue

    if world-map location exists:
        navigate globally
        reobserve
        continue

    if known location memory is reliable:
        navigate there
        reobserve
        continue

    if search area exists:
        bounded local search
        reobserve
        continue

    gather more information

    if still unknown after budget:
        return typed BLOCKED/UNKNOWN,
        not an infinite loop.

============================================================
68. PLAYER DEATH / RECOVERY
============================================================

Death is a Supervisor-level interrupt.

On PLAYER_DEAD:

1. cancel active skill
2. release all keys
3. capture death UI state
4. run DeathRecovery policy
5. restore control only after alive state is verified
6. invalidate stale local target/path
7. preserve primary quest goal
8. re-localize current objective

DeathRecovery implementation may support the current game UI flow already present in the repository.

Do not fake success if automated resurrection is not implemented.

Return BLOCKED_NEEDS_DEATH_RECOVERY when required.

> current interaction
> navigation

- map use
- search
- interaction
- loot

============================================================
99. THE MOST IMPORTANT QUEST RULE
============================================================

THE QUEST OBJECTIVE DOES NOT HAVE TO BE IN THE CAMERA.

When the objective is not visible:

DO NOT immediately return TARGET_NOT_FOUND.

Instead:

1. read current quest/objective
2. check validated local evidence
3. check minimap/navigation cue
4. check world map
5. check reliable memory/context
6. navigate to the best known area
7. re-check minimap
8. perform bounded local search
9. acquire and validate entity/object/mechanic
10. execute deterministic M0 skill
11. verify QUEST CREDIT
12. re-read quest state
13. classify/localize the next stage

This loop is the core of human-like WoW quest execution.
